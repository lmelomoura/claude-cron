        Runs never work in the folder above directly; each one gets its own worktree
    cut from this branch. Leave it empty and the branch is read from that folder at run time,
    which is fine until the checkout is left detached or on somebody's feature branch — then every
    run inherits it. Naming the branch here is what makes runs repeatable no matter what state the
    folder is in. Ending it in * (release/*) takes the newest branch of
    that family, so a project shipping through release trains is set once instead of pointing at
    last month's train.
        
  
        
  
  
  
        Claude Code keeps
    credentials, settings, plugins, MCP servers and past sessions
    per config directory — one signed-in account each — so this is what puts a project's runs on
    your work account (~/.claude-work) rather than your personal one
    (~/.claude-personal). Leave it empty to inherit whatever
    CLAUDE_CONFIG_DIR the scheduler runs with. It is typed, not browsed: the folder
    picker hides dot-directories. Keep it stable once runs exist — a resumed session is looked up
    inside the account that created it.

        One: the working directory from step 1, cut from the base branch you
      set there. There is nothing to fill in here — the run's worktree is made from that folder.
        
    
  
        
  
        
    
        
    
    
        Use this when one ticket touches several repositories at once. Each row gets
      its own worktree inside the run's directory, and the agent reaches the others through
      CC_RUN_MANIFEST. One row must have the same path as the working directory in
      step 1 — that is the repo the agent starts in, and a run whose rows all point
      elsewhere is refused before it begins. Name is the worktree's folder name.
      Base is per repo here, so the field in step 1 is put away while this is on; empty
      still means "read it from that checkout", and * (release/*) still
      takes the newest of a family.
        
    
  
        
  
  
        
    
    
        
      
      
          
    
          
    
  
          
  
          Turn this off and every run of this project works in the same folder. Two agents
    then share one working tree: one git checkout silently moves the other off its
    branch, and its work is gone. Worse, anything else pointed at that folder — a Docker bind-mount,
    your editor, a running dev server — gets served whichever branch an agent happened to leave
    behind. Auto is the safe default and isolates whenever the cwd is a git repo;
    Always refuses to run in the cwd even when the git check is inconclusive — use it when
    something outside claude-cron depends on that folder. Only choose Off for a cwd nothing
    else reads.
          
  
          

  
          
  
          A fresh worktree has no .env, no vendor, no
    node_modules — they are gitignored, so no checkout produces them. These scripts
    put them there.
          
  
  
  
  
  
          They run
    once per repo, with the working directory set to that repo's worktree and the run in the
    environment: CC_REPO_NAME, CC_REPO_PATH (the canonical checkout to copy
    from), CC_WORKTREE, CC_BASE, CC_RUN_DIR,
    CC_RUN_MANIFEST, CC_PROJECT, CC_JOB_ID. A non-zero
    up aborts the run rather than hand an agent a half-built tree. Anything with a
    global name — a herd site, a compose project — must derive it from $CC_RUN_DIR, or
    two runs of the same repo collide.
